# Singfolio v1.0 画面設計

## 1. ナビゲーション

ボトムタブは3つ。

-   **Songs** --- レパートリー管理
-   **Practice** --- 練習中の曲
-   **Profile** --- 見せる・設定

メイン導線は `Songs` とする。

## 2. 画面遷移

``` text
                     Singfolio
                         │
          ┌──────────────┼──────────────┐
          │              │              │
        Songs         Practice        Profile
          │              │              │
          │              │         ┌────┴────┐
          │              │         │         │
      Song Detail    Song Detail  Show Mode  Tags / About
          │                                      │
       Add / Edit                          Open source licenses
```

設定（Appearance・Language・Suggestions）は、Profile 自身に並ぶ（§9）。Tags・Artists・About は、
Profile から開く別の画面。Open source licenses は、About から開く画面。

v1.0ではログインを必須にしない。

公開Web・Requestsは将来追加する。

### 起動時の例外

起動に失敗したときや、画面の描画に失敗したときは、タブを出さず、専用のエラー画面で伝える
（アプリ全体で1つ。ルートの `ErrorBoundary`）。エラー画面はDBに触れない（起動時の失敗では
DBを読めないことがある）ため、言語は保存したLanguageの設定ではなく、常に端末の言語で出す。
配色は、起動に失敗したときは端末の設定に従い、起動が終わった後の描画の失敗では、保存した
Appearanceのまま（起動時に端末へ反映済みのため）。

-   **アプリより新しいDB**（ストアで古い版へ戻した場合など）：「アプリの更新が必要です」と
    伝える。やり直しても開けないため、ボタンは出さない。DBは変更していない旨も伝える。
-   **それ以外の起動時の失敗**（DBを開けないなど）：汎用の文言と「もう一度試す」ボタン。
    押すと起動の処理を最初からやり直す。原因は利用者に見せない。
-   **起動後の画面の描画の失敗**：同じ汎用のエラー画面（タブも隠れる）。「もう一度試す」を
    押すと、アプリの画面を作り直し、先頭の画面（Songs）から始める（開いていた画面は残らない。
    iOSで確認）。先頭の画面自体が失敗する場合は、やり直しても同じ失敗になる（アプリの
    再起動が要る）。画面のデータの読み込みの失敗も、同じエラー画面に任せる（Songsは、
    読み込みの失敗を、描画の中で例外として投げ直す）。画面（ルート）ごとの `ErrorBoundary` は置かない。失敗してもタブへ戻れる
    ようにしたい画面が出てきたら、その画面に足す（2. 以降の画面を足すときに判断する）。
-   **存在しない画面**（`singfolio://...` のリンクなど）：「画面が見つかりません」と、
    曲の一覧へ戻るボタン。通常の画面と同じく、保存した言語・配色に従う。
-   スプラッシュは、DBの初期化と設定の読み込みが終わり、最初の画面を描画できるまで残す。
    エラー画面を出すときは閉じる。

## 3. Songs

アプリのホーム画面。

### 表示

``` text
Singfolio                              ＋

  84             12             23
 Ready         Practice         Want

Search songs or artists

[ All ] [ J-Pop ] [ Rock ] [ Acoustic ]

Ready to sing  84         ⇅ Recently updated

チェリー                                 My Key
スピッツ                                   +2
J-Pop · Acoustic

HANABI                                   My Key
Mr.Children                                -
J-Pop · Ballad

天体観測                                 My Key
BUMP OF CHICKEN                            -1
Rock · Anime
```

ヘッダーの題はブランド名（左寄せ）。件数タイル・検索欄・タグのチップ・見出し・曲の行は、
1つのリストとして一緒にスクロールする（検索欄は固定しない）。

### 操作

-   **ステータスで絞り込む**: Ready / Practice / Want の件数タイルが、そのまま絞り込みの
    切り替え。押すとそのステータスの曲だけを表示する。起動時は Ready。選択中のタイルを
    もう一度押すと、ステータスで絞らない（見出しは「すべての曲」）。
    件数は、検索・タグに関係なく、全曲のステータスごとの数。
-   **曲を検索**: 曲名またはアーティストに含まれる文字列。入力するたびに絞り込む。
    大文字小文字・全角半角・ひらがな/カタカナの違いは区別しない（`ちぇりー` で `チェリー`
    が見つかる）。アーティストは、名前だけでなく**読み**でも探せる（`よねづ` で `米津玄師`）。
    曲名の漢字は読みを持たないので、読みでは探せない（`singfolio-data-model.md`「曲の一覧」）。
-   **タグで絞り込む**: 検索欄の下のチップ（横スクロール）。1つだけ選べる。`All` または
    選択中のチップをもう一度押すと解除。タグが1つも無いときは、チップの列を出さない。
    作成済みのタグはすべて出す（曲が付いていないタグも）。選んでいたタグが、Settingsで
    削除された場合は、絞り込みを外す。
-   **並び替え**: 見出しの右のボタンから、下から出るシートで選ぶ。Recently updated（更新が
    新しい順。既定）/ Recently added（追加が新しい順）/ Title（曲名のA→Z）/ Artist
    （アーティストのA→Z）。向きは、それぞれ固定（逆順は持たない）。Title / Artist は、
    **五十音順**（ひらがな・カタカナを混ぜる。記号・数字・英字が先、かなが次、漢字が最後）。
    Artist は、アーティストの**読み**で並べる（漢字・英字の名前も、読みの位置に来る）。Title は、
    曲名の読みを持たないので、漢字の曲名は、かなの後ろに文字コード順で並ぶ
    （`singfolio-data-model.md`「曲の一覧」）。
-   曲をタップ → Song Detail
-   `＋`（ヘッダーの右） → Add Song

絞り込み・並び替えの状態は、アプリを開いている間だけ保持する（端末には保存しない。
起動すると、Ready・タグなし・検索なし・Recently updated に戻る）。条件はすべて満たす曲だけを
出す（AND）。見出しの数字は、表示中の曲の数。

他の画面で曲やタグが変わったあと（Song Detail・Practice・Settingsなど）にタブへ戻ると、
読み直す。リンクで Song Detail を直接開いた場合も、Songs は一度もフォーカスされないまま
読み込むので、Song Detail から戻った最初のフォーカスで読み直す（起動で最初に出たとき
だけ、最初のフォーカスは読み込みと重なるので読み直さない）。Practice の一覧も同じ。

行には、曲名・アーティスト・タグ（` · ` 区切りの1行）を左に、**My Key** を右に出す（見出し `My Key` と、
`+2` / `-2`。歌う前に見たい情報なので、一覧に出す）。原曲のまま（`0`）の曲は、`-` を控えめな色で出し
（Song Detail・Add / Edit Song の `Original` とは違い、行ごとに並ぶので短くする。読み上げは
「Original」）、ずらしている曲だけを濃い色の太字で出す。
Private Note は出さない（人に見せる画面 Show Mode の行は、My Key を出さない別の行）。
タグが付いていない曲は、タグの行を出さない。

### 空の状態

| 状況 | 表示 |
|---|---|
| 曲が1つも無い | 「まだ曲がありません」と、Add Song を開く「曲を追加」ボタン |
| 検索・タグで絞り込んで0件 | 「一致する曲がありません」、見出しの名前（「歌える曲」など）を含む案内、「検索とタグをクリア」ボタン（ステータスは変えない） |
| ステータスだけで絞って0件 | ステータスごとの1行の案内 |

## 4. Add / Edit Song

曲の登録・編集画面。同じ入力画面（`ui/SongForm.tsx`）を、追加（`app/song/new.tsx`）と
編集（`app/song/[id]/edit.tsx`）で使う。タブバーを隠した全画面で、Stackに積む。

追加は、Songsの `＋`（ヘッダーの右）と、曲が1つも無いときの「曲を追加」ボタンから開く。
編集は、Song Detail の Edit から開く。存在しない曲のIDで編集を
開いた（開いている間に曲が消えた場合を含む）ときは、「曲が見つかりません」と、曲の一覧へ
戻るボタンを出す。

### 項目

**Song** - Artist * - Sort name（日本語の画面では「読み」） * - Title *

**Status** - Ready - Practice - Want

**My Key** - Original - - / + 数値

**Tags** - 複数選択 - 新規タグ作成

**Private Note** - 自由入力

`*` のみ必須。

素早く登録できることを優先し、Title + Artist（と、その読み）だけでも保存可能とする。
読みは、ほとんどの場合、自動で入る（下の「読み」）。

``` text
< (戻る)        Add Song        [ Save ]

Artist *
[                              ]
Sort name *   Used to sort this artist's songs. ...
[                              ]
Title *
[                              ]

Status
[ Ready ] [ Practice ] [ Want ]

My Key
 ( − )     Original     ( + )

Tags
Tags may appear in Show Mode.
Keep private details in Private Note.
[ J-Pop ] [ Rock ] [ Acoustic ]
[ New tag                 ] ( + )

Private Note
[                              ]
```

-   **Save** はヘッダーの右（キーボードを出したまま押せる）。保存すると前の画面へ戻る。
-   **入力の順は、Artist → 読み（Sort name）→ Title**。アーティストが決まると、読みが入り、曲名の
    候補も入力したアーティストで絞れるため（曲名の候補の検索語。「候補」節）。追加は、開くと
    Artistにフォーカスが入り、すぐ入力できる。改行（Enter）は、Artist → Title と移る（読みが空の
    ときだけ、Artist → 読み → Title）。読みは、ほとんどの場合、自動で入るので、飛ばす。
    Titleは3番目で、候補がキーボードに隠れないよう、フォーカスが入ったら、欄が上に来るまで
    スクロールする（スクロールすると、キーボードが閉じて欄が外れ、候補が消えるため）。
-   **Status** の既定は Ready（追加のとき。中心の体験「曲を登録 → Readyにする」のため。
    Songsで選んでいるステータスには依存しない）。
-   Title / Artist が空（空白だけを含む）のまま Save すると、保存せず、両方の欄の下に
    エラーを出し、画面の順（Artist → 読み → Title）で最初の問題の欄にフォーカスを移す。入力すると、
    その欄のエラーが消える。それ以外の保存の失敗は、ダイアログで伝える。
-   **読み（Sort name）**: アーティストの並び替え用の名前で、**必須**（空では保存できない。
    エラーは欄の下に出す）。**そのアーティストの全曲に効く**（読みを曲ごとに持たない）。
    -   **初期値**は、Artist を入れる・候補から選ぶと入る。登録済みのアーティスト（`artistNameKey`
        が同じ。大文字小文字・全角半角を区別しない）なら、その読み。**日本語の設定**では、そうでなければ
        **辞書**（端末内の同梱ファイル。`singfolio-data-model.md`「アーティストの読みの辞書」。
        `ELLEGARDEN` → `エルレガーデン`、`米津玄師` → `よねづけんし`）の読み。どれも無ければ、
        名前から決める（`defaultReading`）: 英語の設定は、名前そのまま（`The Beatles`。`The` を外して `Beatles` にする
        のは、利用者が書き換える）、日本語の設定は、かなだけの名前ならそのまま、漢字・英字を含む名前は
        **空**（入力してもらう）。自分で書き換えた後は、Artist を変えても上書きしない（候補を選んだ
        ときは、また初期値に戻す）。
    -   **日本語の設定**では、読みに漢字・英字（全角を含む）を含められない（かな・長音・中点・
        空白・数字・記号は可）。保存のとき、「ひらがな・カタカナで入力してください（漢字・英字は使えません）」
        を欄の下に出す。**読みを変えたとき**（新しいアーティストを含む）だけ確認し、編集画面を開いて、
        保存済みの読み（英語の設定で入れた `Beatles` など）のまま保存するときは、咎めない。
        **英語の設定**は、空でなければ自由。
    -   読みは、並び替え（Songs の Artist・Show Mode のアーティスト別）と、検索に使う。
    -   読みを変えて保存すると、そのアーティストの全曲の読みが変わる。曲の最終更新は、曲の内容が
        変わったときだけ更新する（読みだけの変更では更新しない）。
-   アーティスト名は、同じアーティスト（大文字小文字・全角半角を区別しない）の別の表記で入れても、
    既存のアーティストに付く（名前は、最初に登録した表記のまま。変えるのは Artists 画面）。
-   **My Key** は `−` / `+` で半音ずつ動かす。0は「Original」と出し、それ以外は `+2` / `-2`。
    選べる範囲は上下12半音（1オクターブ。`src/domain/keyOffset.ts`）で、端では、その向きの
    ボタンを無効にする。これは入力画面の範囲で、保存する値の制限ではない
    （`singfolio-data-model.md`「曲の入力」）。
-   **Tags**: 作成済みのタグをチップで複数選ぶ。新しいタグは、下の入力欄に書いて追加する
    （Enter・`＋`。iOSは、続けて追加できるよう、Enterでキーボードを閉じない。Androidは
    閉じる）。追加した新しいタグは、選択中のチップとして並び、押すと取り消せる。
    **新しいタグは、曲を保存するときに、曲と同じトランザクションで作る**（保存せずに戻った
    とき、保存に失敗したとき、どちらも使われないタグが残らないようにするため）。入力欄に
    書いたまま Save した名前も、追加したものとして扱う。既存のタグと同じ名前（正規化して、大文字小文字を同一視。
    `singfolio-data-model.md`「タグ名」）は、新しく作らず、そのタグを選ぶ。
-   変更があるまま戻る（戻るボタン・iOSのスワイプ・Androidの戻る操作）と、「変更を破棄
    しますか？」の確認を出す。保存して戻るときは出さない。

### 候補（サジェスト）

Title / Artist を入力している間、候補を欄の直下に出す（オーバーレイにしない。キーボードの
余白と同じスクロールの中に置く）。候補は補助で、出なくても、使わなくても、自由に入力して
保存できる。

-   **曲名の欄**: 曲の候補（`曲名 / アーティスト`）を出す。選ぶと、**曲名とアーティストの
    両方**を候補の値で置き換える（候補は組なので、片方だけだと組が崩れる）。登録済みの
    （曲名, アーティスト）の組には「登録済み」を付ける（重複登録は止めない）。
-   **アーティストの欄**: 登録済みのアーティストを先に、外部の検索で見つかったアーティストを
    後に出す。選ぶと、**アーティストの欄だけ**を置き換え、曲名には触れない。共演の表記
    （`A & B`、`feat.`、`×`）は分割せず、単独の名前より後ろに並べる。
-   検索語は、曲名の候補は曲名（この画面でアーティストを入力した・候補から選んだときは、
    それも加える。編集画面を開いたときから入っているアーティストは、編集していないので
    加えない）、アーティストの候補はアーティスト。2文字未満は検索しない（登録済みのアーティストの候補は1文字から出す）。
    ひらがな・カタカナ・全角半角・大文字小文字を同一視して探せ、かな入力で漢字の曲名も
    見つかる（`ぐれんげ` → `紅蓮華`）。
-   **送信のタイミング**: 入力欄を**編集した**ときだけ。フォーカスしただけ・開いたときの
    既存の値では送らない。入力が止まってから送る（登録済みのアーティストの候補は待たずに出す）。
-   **候補の整形はしない**。`(Live)`・`- Remastered` などの版の表記もそのまま出す。選んだ
    後に編集できる。版の表記を含む候補（Live・Cover・Karaoke・オルゴールなど）は、削らずに
    後ろへ並べる。同じ（曲名, アーティスト）の候補は1つにする。
-   **古い結果は捨てる**。入力の変更・候補の選択・別の欄へのフォーカス移動・画面を閉じる、の
    いずれでも、返ってきた古い結果は出さない。候補を選んで欄が書き換わっても、再検索しない。
-   **失敗しても止めない**。通信できない・遅い・回数の制限に当たったときは、外部の候補が
    出ないだけで、入力も保存もできる。制限などの失敗の後は、一定時間は外部へ送らない（その間も
    登録済みのアーティストの候補は出す）。失敗を「見つからなかった」として覚えない。探せなかったとき（予算切れ・停止中・失敗）は、
    直前の候補をそのまま残す（検索語を打ち足している・消して戻している間だけ。別の語に打ち直した・
    0件・検索語が短くなる・フォーカスが外れるときは消える）。
-   **変換で別の語になったとき**（`ぐれんげ` → `紅蓮華`）は、候補がいったん消えて、新しい語の
    結果が出る。自然な動きとして決めたもので、前の候補を残す・高さを保つ工夫はしない。
-   **表記する**: 外部へ検索語を送る間は、候補の欄に提供元（`Suggestions from Apple` /
    `候補の提供元: Apple`）を出す。候補が0件のときも出す。設定でオフのときは出さない。
-   **ストア**: 実際に使う表示言語が日本語なら日本のストア、それ以外は米国のストアで探す
    （表記が変わる。例: `千本桜` / `Senbonzakura`）。端末の地域では決めない。
-   候補は最大5件（アーティストは4件）。キーボードの上に収めるため、行は2行までの低い高さに
    する。各行はボタンとして読み上げる（`曲名、アーティスト`。登録済みならそれも）。

### タグに関する注意事項

タグはShow Modeに表示される。人に見せたくない内容はPrivate Noteに入力するよう、
タグ欄の近くで短く案内する。

``` text
Tags may appear in Show Mode.
Keep private details in Private Note.

タグはShow Modeに表示されます。
人に見せたくない内容はPrivate Noteに入力してください。
```

案内は、Tagsの見出しの下に、常に表示する（初回だけ・情報アイコンなどにはしない。曲を
登録するたびに目に入り、タグ欄の近くで読めるため）。

## 5. Song Detail

登録した曲の詳細画面。

``` text
チェリー
スピッツ

STATUS
● Ready to sing

MY KEY
-2

TAGS
J-Pop
Acoustic

PRIVATE NOTE
2番の歌詞を確認
サビは問題なし。

────────────────

Edit
Delete song
```

ここからステータス変更も可能とする。

`Practice → Ready` などを簡単に行えるようにする。

実装（`app/song/[id]/index.tsx`）は、Stackに積む全画面。ヘッダーには戻るボタンだけを出し、
題は付けない（曲名は本文の先頭に出す）。

-   **曲名・アーティスト**: 長いときは折り返して、全文を出す（一覧のように省略しない）。
-   **Status**: Add / Edit Song と同じ3択（`ChoiceRow`）を、そのまま変更の操作にする。
    押すとすぐ保存し（Saveは無い）、`updatedAt` も更新する（`setStatus`）。選択中のステータスを
    押し直しても何もしない。保存に失敗したら、ダイアログで伝える。
-   **My Key**: `Original` / `+2` / `-2`（Add / Edit Song と同じ表記）。
-   **Tags・Private Note**: 無い曲では、項目ごと出さない（空の見出しを並べない）。Private Note は
    改行を入力どおりに出す。ここは管理する画面なので、My Key・Private Note を出してよい
    （Show Mode とは別の画面）。
-   **Edit**: 末尾の区切り線の下のボタン。Edit Song を開く。
-   **Delete song**: Edit の下のボタン（文字は `error` の色）。曲の削除は、この画面だけに置く
    （Edit Song には置かない）。消す曲のキー・メモ・タグをその場で見て判断でき、削除のあとに
    畳む画面が1枚で済み、Edit Song の「変更を破棄しますか？」の確認と重ならないため。
    押すと確認のダイアログ（「曲を削除しますか？」。曲名を添え、元に戻せないと伝える。
    キャンセル / 削除）を出し、削除を選ぶと曲を消して、前の画面（SongsやPractice）へ戻る。
    取り消し（Undo）は無い。付いていたタグは残る（`singfolio-data-model.md`）。
    削除に失敗したらダイアログで伝え、この画面に残る。削除できたあと戻るまでの間は、
    ステータスの変更・Edit・もう一度の削除を受け付けない（戻る操作が重ならないように）。
    削除している間に、戻る操作でこの画面を離れていたら、削除だけ済ませて、それ以上は戻らない
    （もう1枚戻ってしまうため）。リンクから直接開いても、下にタブが積まれるので
    （`app/_layout.tsx` の `initialRouteName`）、戻る先はある（戻る先が無いときに曲の一覧を
    開く分岐は、念のためで、通常は通らない）。
-   Songs の行をタップして開く。開いたとき、および上に重ねた Edit Song から戻ったときに、
    曲を読み直す（戻ったときは、前の内容を出したまま読み直して、空の画面を挟まない）。
    Songs は、この画面から戻ったときに自分で読み直す（§3）。
-   Songs の行・Edit ボタンを素早く連打しても、同じ曲の Song Detail・Edit Song は重ならず、
    1枚だけ開く（Add Song も同じ。`app/_layout.tsx` の `dangerouslySingular`）。
-   存在しない曲のID・開いている間に消えた曲（ステータスを押した時点で消えていたことが
    分かる場合を含む）は、Edit Song と同じ「曲が見つかりません」と、曲の一覧へ戻るボタンを出す。

## 6. Practice

現在練習している曲に集中する画面。

``` text
Practice

12 songs

Search...

怪獣
サカナクション

Last updated: Today

[ Mark as Ready ]


晩餐歌
tuki.

Last updated: Sep 28

[ Mark as Ready ]
```

### 操作

-   練習中の曲を一覧表示
-   曲をタップ → Song Detail
-   `Mark as Ready`
-   検索

練習履歴などの高度な管理はv1.0では行わない。

実装は `app/(tabs)/practice.tsx`（一覧の行は `ui/PracticeRow.tsx`）。

-   **一覧**: ステータスが Practice の曲だけ。更新が新しい順（`updatedAt` の降順）で固定し、
    並び替え・タグの絞り込み・ステータスのタイルは置かない（練習中の曲に集中する画面のため）。
    行には、曲名・アーティスト・最終更新を出す（Songs の行と違い、タグは出さない。
    My Key・Private Note も出さない）。ヘッダーの `N songs` / `N曲` は、表示中の曲の数
    （検索で絞ると減る。Songs の見出しの数字と同じ）。
-   **最終更新**: 今日なら `Last updated: Today` / `最終更新：今日`。それ以外は日付
    （`Last updated: Sep 28` / `最終更新：9月28日`。今年でなければ年も出す: `Sep 28, 2025` /
    `2025年9月28日`）。「昨日」などの言い換えはしない。日の区切りは端末のタイムゾーンで、
    日付の書き方は `src/i18n/formatDay.ts`（`Intl` は使わない）。「今日」は、一覧を読み込んだ時刻と、
    アプリがバックグラウンドから戻った時刻（一覧は読み直さず、日付の文字列だけを更新する）で
    決める。昨夜開いたまま閉じて翌朝開いたときも、昨日の曲が「今日」のままにならない。画面を
    見ている最中に日付をまたいだ場合だけは、読み直す（タブの切り替え・検索の変更）まで変わらない。
-   **検索**: Songs と同じ（曲名・アーティスト名・アーティストの読み。大文字小文字・全角半角・
    ひらがな/カタカナを区別しない。§3）。検索語は、アプリを開いている間だけ保持する。検索欄は、件数と一緒に一覧の
    先頭にあり、一覧と一緒にスクロールする。
-   **Mark as Ready**: 各行の、曲の情報の下のボタン。押すとすぐ Ready にし（確認は無い。
    Song Detail のステータス変更と同じ `setStatus`。`updatedAt` も更新する）、一覧を読み直す。
    Ready の曲は Practice の一覧に出ないので、行が消え、件数が減る（検索中も同じ。0件になれば
    空の状態）。取り消しの操作は無い（戻すときは Song Detail でステータスを変える）。同じ曲の
    ボタンの連打は1回にまとめる（別の曲のボタンは続けて押せる）。失敗したらダイアログで伝え、
    行は残す。曲が既に無かったときは、何も伝えずに一覧から消す。
    曲の情報（押すと Song Detail）とボタンは、兄弟の要素にする（`ui/PracticeRow.tsx` のコメント）。
    そのため、行を押せるのは曲の情報の部分とボタンだけで、ボタンの右側と行の下の余白は押しても
    何も起きない（Songs の行は、行のどこを押しても開く）。
    ボタンの読み上げには、どの曲かを添える（`Mark as Ready, 怪獣`。行ごとに同じ名前のボタンが並ぶため）。
-   他の画面で曲が変わったあと（Song Detail でステータスを変えた・削除したなど）に戻ると、
    読み直す（§3の読み直しと同じ `ui/useFocusRefreshKey.ts`）。

### 空の状態

| 状況 | 表示 |
|---|---|
| 練習中の曲が1つも無い | 「練習中の曲はありません」と、Practice にした曲が並ぶという案内 |
| 検索して0件（練習中の曲はある） | 「一致する曲がありません」と「検索をクリア」ボタン |

練習中の曲が無いときは、検索語が残っていても、検索のせいではないので、前者を出す。

## 8. Show Mode

Singfolioの重要機能。

友人などにスマートフォンを見せて、「この中から選んで」と使うための閲覧専用画面。

``` text
             Singfolio

        What should I sing?

      84 songs ready to sing

Search songs or artists...

[ All ] [ J-Pop ] [ Rock ] [ Ballad ]

スピッツ                              8

チェリー
ロビンソン
楓
空も飛べるはず


Mr.Children                         12

HANABI
Sign
しるし
Tomorrow never knows
```

### 表示する

-   曲名
-   アーティスト（アーティスト別のときは、曲の上の見出し。曲名順のときは、曲名の下）
-   タグ

### 表示しない

-   My Key
-   Private Note
-   Want
-   その他管理情報

Show Modeから編集操作はできない。

画面右上の `×` で通常画面へ戻る。Androidは戻るキー（戻るジェスチャーを含む）でも閉じる。
iOSの、画面の端からのスワイプでは閉じない（人に渡して触られても、管理の画面へ戻らない
ように、`gestureEnabled: false` で明示している）。

### 仕様

-   **対象はReadyの曲だけ**。PracticeとWantの曲は、一覧にも、件数にも、タグの絞り込みにも
    出ない。
-   **アーティスト別**。見出しは、アーティスト名と、右端にそのアーティストの曲数（表示中の
    もの）。曲は曲名順。アーティストの並びは Songs の「アーティスト順」と同じ（アーティストの
    **読み**の五十音順。漢字・英字の名前も、読みの位置に来る。`singfolio-data-model.md`「曲の一覧」）。
    大文字小文字・全角半角だけが違う表記（`Mr.Children` と `MR.CHILDREN`）は、同じアーティスト
    なので、1つの見出しにまとまる（名前は、最初に登録した表記）。見出しは、スクロールしても上に残る。
-   **並び替え**: タグのチップの下の右端のボタン（Songs の並び替えと同じ部品。押すと、下から出る
    シートで選ぶ）。**Artist**（既定。上の、アーティスト別）/ **Title**（曲名のA→Z。見出しは無く、
    1つの一覧で、各行の曲名の下にアーティスト名を出す）。同じ曲名は、アーティスト順。曲名・
    アーティストの順は Songs と同じ（五十音順。曲名の漢字は、かなの後ろ）。更新日・追加日の順は選べない
    （人に見せる画面に、管理の情報を持ち込まない）。選択肢の文言は、Songs の `Title` / `Artist` と
    同じ。検索欄と同じく、Readyの曲が無いときは出さない。
-   **件数**（「84 songs ready to sing」）は、Readyの曲の総数。検索・タグで絞っても変わらない。
-   **検索**は Songs と同じ判定（曲名・アーティスト名・アーティストの読み。大文字小文字・全角半角・
    ひらがな/カタカナを区別しない）。**タグ**は、Readyの曲に付いているタグだけをチップに
    出す（Songs は作成済みのタグをすべて出す。Ready以外の曲にだけ付いたタグや、曲が付いて
    いないタグは、選んでも何も出ず、見せない曲の手がかりにもなるため出さない）。1つだけ
    選べ、`All` か選択中のチップをもう一度押すと解除。
-   検索・タグ・並びの状態は、画面を閉じると捨てる（開くたびに、全部が見える状態から始まる。並びは Artist）。
-   **行は押せない**。Song Detail は My Key・Private Note を出す管理の画面なので、人に見せる
    画面から開かない。
-   **管理情報は、画面が持たない**。画面は `songs` ではなく `show`（Service）から、My Key・
    Private Note・ステータスを持たない形（`ShowSong`）で受け取る（出さないのではなく、
    出せない）。タグも、`id` と `name` だけ（`ShowTag`）。`Tag` に項目が増えても届かない。
-   空の状態: Readyの曲が1つも無いときは案内だけ（検索欄・タグは出さない。読み込みの前は検索欄を
    出しておくので、このときだけ、読み込みが終わったところで検索欄が消える）。絞り込みに
    一致する曲が無いときは、案内と、検索とタグのクリアのボタン。
-   開く入口は、Profile の `Show My Songs`（7. Profile）。リンク `singfolio://show` でも開く。
    タブバーを隠した全画面で、下から出入りする。連打で重ねて開かない。

## 9. Settings

Profile（§7）の下半分に、`Appearance` / `Language` / `Suggestions` / `Tags` / `Artists` / `About` の順に並ぶ。

-   `Appearance`・`Language` は、右に今の設定を出し（`System`・`日本語` など）、押すと、下から出るシート
    （Songs の並び替えと同じ部品）で選ぶ。選ぶと、保存してから反映し、保存に失敗したときは、
    ダイアログで伝えて、表示は変えない。
-   `Suggestions` は、行の中のスイッチ。切り替えは、保存の完了を待たずに反映し、保存に失敗したら
    元に戻して、ダイアログで伝える。
-   `Tags`・`Artists`・`About` は、押すと別の画面を開く（連打で重ねない）。ヘッダーの題は、項目の名前。
    `About` の中に、`Open source licenses` の行がある（下の「Open source licenses」）。
-   読み込み前（数ミリ秒）は、設定の並び全体を出さない（項目が後から増えて、位置が動かないように）。

### Appearance

-   System
-   Light
-   Dark

デフォルトはSystem。

-   アプリ全体（ネイティブの描画を含む）のカラースキームを切り替えるため、ステータスバーや
    ダイアログも設定に従う。端末（OS）の設定は変えない。
-   起動画面（スプラッシュ）だけは、アプリが起動する前に表示されるため、この設定ではなく
    端末の設定に従う（端末がダークでAppearanceがLightのときは、ダークの起動画面のあと
    ライトの画面になる）。Androidでは、アプリを終了して同じプロセスのまま再び開いた
    直後にも、Appearanceが System 以外のときは、設定を反映するまでの短い間、端末の配色の
    画面が見える。

### Language

-   English
-   日本語

`System` は無い（言語の設定は、実際に使う言語そのもの。Appearanceと違う）。アーティストの読みの
入力ルールが表示言語で変わる（日本語は、かなだけ。Add / Edit Song の「読み」）ため、端末の言語の
変更で、知らないうちにルールが変わらないようにしている。

-   English / 日本語は、その言語自身の名前で出す（言語が分からなくなっても選び直せるように）。
-   初回起動（未保存）で、端末の言語の優先順に見て、最初に対応している言語（`ja-JP` → 日本語）を
    決めて、保存する。どれも対応していなければ English。以後は、端末の言語が変わっても追従しない。
    旧版が `system` を保存していた場合も、起動時に端末の言語から決め直して保存する。
-   切り替えるときは、確認のダイアログを出す。どの切り替えでも出す。題は「言語を変更しますか？」、
    本文は「○○に切り替えます。アーティストの読みの入力ルールも変わります。」、ボタンは
    キャンセル / 変更。文言は、切り替える前の言語で出る。変更すると、保存してから、アプリを
    再起動せず全画面にすぐ反映する。保存に失敗したときは、ダイアログで伝えて、表示は変えない。
-   書体は表示言語に従う（English → Inter、日本語 → Noto Sans JP）。ヘッダーの題・タブの
    ラベルも含め、言語を切り替えるとすぐ変わる。ユーザーが入力した日本語を English の画面で
    出すときは、Inter に日本語の字が無いため、OS（端末）のフォントで表示される（端末の言語に
    日本語が無いと、漢字が中国語の字形になりうる。未確認。許容している）。
-   iOSは、アプリの対応言語（`CFBundleLocalizations`）を app.json で宣言している。
    宣言が無いと、iOSの標準の文言（コピー/ペーストのメニュー、ダイアログのボタンなど）が
    日本語の端末でも英語のままになる（Appleの説明による。未確認）。宣言すると、OSの設定
    アプリのSingfolioに、アプリごとの言語の項目が出る（Appleの仕様。未確認）。
    初回起動の言語は、OSが返す言語の優先順から決める（起動引数 `-AppleLanguages` で言語を
    変えて、従うことをiOSシミュレータで確認済み。設定アプリの項目からの変更は未確認）。
    以後は、アプリ内の設定が優先する。OSの設定アプリで言語を変えても、アプリの文言は
    変わらず、OS標準の文言だけが変わる。
-   Androidは、アプリごとの言語（Android 13以降のOSの機能）を宣言していない。言語の操作は
    アプリ内のLanguageに一本化する。Androidの標準の文言は端末の言語に従う。
-   OS標準の部品の文言は、アプリ内のLanguageではなく、端末（iOSでOSの設定アプリで選んだ
    アプリの言語を含む）の言語に従う。そのため、アプリ内で選んだ言語が端末と違うと、
    ずれる（`Alert.alert` のボタンを省略したときの既定の「OK」など）。文言を指定できる
    ものは、省略せず指定する（CLAUDE.md「言語」）。

### Suggestions

曲名・アーティストの候補（Add / Edit Song）を、外部の楽曲検索から出すかどうか。オン / オフ。
デフォルトはオン。

-   説明文: 「入力中の曲名・アーティスト名を Apple に送って、候補を探します。それ以外は
    送りません。」（English: "What you type in Title and Artist is sent to Apple to find
    suggestions. Nothing else is sent."）
-   オフにすると外部へは何も送らない。登録済みのアーティストの候補は、端末内だけで出す。
-   外部の検索が使えない状態（ビルドで無効にしたとき）は、この項目も、候補の提供元の表記も
    出さない。

### Tags

作成済みタグの管理（Profile の `Tags` から開く画面）。

-   一覧は、タグ名の昇順（Songs のチップと同じ）。1つも無いときは、「まだタグがありません」と、
    曲に付けたタグがここに並ぶ案内。タグを作るのは曲の追加・編集で、ここでは作らない。曲の数は
    出さない。
-   行を押すと、名前の変更と削除のダイアログ（画面の上の方に出す。Androidは、キーボードが出ても
    画面が縮まないので、下に置くと入力欄が隠れる）。入力欄に今の名前が全選択で入る。
    **保存**で名前を変え、ダイアログを閉じて一覧を読み直す。空の名前、既にある名前（正規化して、
    大文字小文字を区別しない。`Rock` と `ROCK`）のときは、入力欄の下に理由を出して、開いたままに
    する（入力を変えると、その文言は消える）。タグが既に無いときは、入力を直しても解消しないので、
    ダイアログを閉じて一覧を読み直す。名前を変えても、曲の最終更新は変わらない。
-   **`Delete tag`** は、確認のダイアログ（「“名前” をすべての曲から外します。曲は削除されません。」）
    のあと、削除して、ダイアログを閉じる。付いていた曲からは外れ、曲は残り、その最終更新も変わらない。
    Songs で選んでいたタグが消えたときは、Songs が絞り込みを外す（§3）。
-   名前の変更・削除は、Songs へ戻ったときに読み直されて、反映される。

### Artists

アーティストの名前と読みの管理（Profile の `Artists` から開く画面。日本語の画面では「アーティスト」）。

-   一覧は、アーティストの**読みの五十音順**（記号・数字・英字が先、かな、漢字の順。`singfolio-data-model.md`
    「曲の一覧」）。行は、名前・読み（その下に小さく）・曲数（`3 songs` / `3曲`）。1つも無いときは、
    「まだアーティストがいません」と、追加した曲のアーティストがここに並ぶ案内。アーティストを作るのは
    曲の追加・編集で、ここでは作らない。曲が1つも無くなったアーティストは、自動で消える（曲を削除する、
    アーティストを付け替える）ので、削除の操作は無い。
-   行を押すと、名前と読みの変更のダイアログ（画面の上の方に出す。理由は Tags と同じ）。名前の欄が先に
    フォーカスされる。**保存**で変え、ダイアログを閉じて一覧を読み直す。空の名前、別のアーティストと
    同じ名前（大文字小文字・全角半角を区別しない。`Queen` と `QUEEN`。大文字小文字だけを変えるのは可）
    のときは、名前の欄の下に理由を出して、開いたままにする。読みは、空は不可で、**日本語の設定では
    漢字・英字を含められない**（Add / Edit Song の「読み」と同じ規則。読みを**変えたときだけ**確認する）。
    アーティストが既に無いときは、入力を直しても解消しないので、ダイアログを閉じて一覧を読み直す。
-   変更は、そのアーティストの全曲に効く（名前・読みは、アーティストごとに1か所）。曲の最終更新は
    変わらない。Songs・Show Mode へ戻ったときに読み直されて、反映される。

### About

アプリの名前、バージョン（app.json の `version`）、プライバシーポリシーと Open source licenses への
行、自前で同梱したフォントのライセンス、データ（アーティストの読みの辞書）の出どころ
（Profile の `About` から開く画面）。

-   「Privacy Policy」の行は、バージョンの下に置き、押すとブラウザで公開ページ（`src/legal/legalUrls.ts`。
    `docs/privacy-policy.md` をGitHub Pagesで公開したもの）を開く。App Store の審査は、ストア掲載情報と
    アプリの中の両方に、プライバシーポリシーへのリンクを求める。右端は、画面へ進む矢印ではなく、外へ
    出る印（`open-outline`）にして、ブラウザが開くことを見た目でも伝える。読み上げには「ブラウザで
    開きます」を添える。
-   「Open source licenses」の行は、その下に置き、押すと下の画面を開く（連打で重ねない）。
-   フォントは、書体名・著作権表示・「SIL Open Font License 1.1」を出し、「ライセンスを表示」で全文を
    開閉する。SIL OFL は、フォントを再配布するとき、著作権表示とライセンス全文を付けることを求める。
-   全文は、元の約75桁の改行を、段落の中で詰めて出す（スマホの幅で、折り返しの後に、短い行が
    残らないように）。字は変えない（`src/legal/reflowLicense.ts`）。
-   全文は `assets/fonts/OFL-*.txt` と同じ内容を、`src/legal/fontLicenses.ts` に写している。食い違いは
    `npm test` が検出する。フォントを入れ替えたら直す。
-   **「Fonts」に載せるのは、`assets/fonts/` に自前で同梱した書体（Inter・Noto Sans JP）だけ**。アイコン
    フォントや npm の依存は、Open source licenses に載せる。
-   **「Data」**（フォントの下）: アーティストの読みの辞書の出どころ。「MusicBrainz」の名前と、「アーティストの
    読みの辞書は、MusicBrainz のコアデータ（CC0。パブリックドメイン）から作っています」の説明、
    musicbrainz.org をブラウザで開く行（外へ出る印。`MUSICBRAINZ_URL`）。CC0 は帰属表示を求めないので、
    表記は義務ではない（出どころを示すため）。

### Open source licenses

About から開く画面。アプリに入る、npm の依存・取り込まれたコード・アイコンフォント・ネイティブの
ライブラリの一覧。MIT・ISC・Apache-2.0・BSD・BSL は、著作権表示とライセンスの全文を含めることを
求める。

-   上に、短い説明（「項目を押すと、ライセンスの全文を表示します」）。その下に、名前の順に、1行ずつ
    名前と、「版 · ライセンスの種類」（版が無いもの・1つに決まらないものは、種類だけ）を出す。行を
    押すと、全文（著作権表示を含む）を開閉する。全文の詰め方は About と同じ。共著の著作権表示は1行
    ずつ残す。
-   片方の OS にだけ入るもの（AndroidX など Android の Maven の依存、iOS の SocketRocket）は、その OS
    でだけ出す。まとめた行（AndroidX など）は、開くと、全文の上に、含まれる成果物
    （`group:artifact:version`）を並べる。
-   **載せているもの**（`src/legal/thirdPartyLicenses.ts`。生成物）:
    -   `npm`: JS バンドルに入るパッケージと、autolinking が取り込むネイティブのパッケージ
        （`dependencies` を機械的にたどるのではない。ビルドにしか使わないものが大量に入るため）。
    -   `bundled`: npm のパッケージの中に取り込まれた、別のプロジェクトのコード。expo-router は
        React Navigation を取り込んでいて（`build/react-navigation/`・`build/fork/`・
        `assets/react-navigation/`）、Expo の LICENSE には React Navigation の著作権表示が無いため、
        別の行にしている。
    -   `font`: アイコンフォント `Ionicons (icon font)`（MIT）・`Material Symbols (icon font)`
        （Apache-2.0。Expo の依存で入る）。npm のパッケージ（`@expo/vector-icons`・
        `@expo-google-fonts/material-symbols`）の LICENSE は、そのコードのもので、フォント自体の
        ライセンスではないため、別の行にしている。
    -   `native`: React Native が同梱する C++ のライブラリ、Android の Maven の依存、Maven の成果物が
        `.so` に埋め込んでいる C/C++ のライブラリ。
        React Native のもの: Hermes・Folly・glog・double-conversion・Boost・{fmt}・fast_float・
        SocketRocket（iOS）。版は React Native のマニフェストから読む。Maven の依存は、Gradle の
        `releaseRuntimeClasspath`（制約は除く）を、POM のライセンスで、プロジェクトごとにまとめる。
        埋め込みのもの: Fresco の libjpeg-turbo・libwebp・giflib、zstd-kmp の Zstandard（APK の `.so` で、
        入っていることを確かめた。成果物の版が変わったら、生成が失敗する）。
-   **載せていないもの**: OS・NDK が提供する実行時のライブラリ（libc++ など。LLVM の例外で、
    バイナリでの表記は要らない）、SQLite（パブリックドメイン）、OkHttp の public suffix のリスト
    （APK の中に、出典とライセンスの NOTICE がある）。Maven の成果物の中を、これ以上は掘り下げない。
-   **生成と確認**: `node scripts/generate-licenses.mjs` で作り直す（`node_modules`・`ios/`・`android/`
    が要る。依存を更新・追加したら、必ず作り直す）。`--check` を付けると、作り直した結果が今のファイルと
    同じかを確かめる（ストア提出の前に実行する）。`--check --apk <APK・AAB>` は、さらに、`lib/` の `.so`
    が、把握しているものだけかを確かめる（release のビルドで実行する）。`npm test` が検出するのは、一覧の
    版がロックファイルにあるか、`dependencies` が全部載っているかまで。バンドルに入るものが増えても
    （インストール済みの依存を、新しく import したなど）、テストは気づけないので、`--check` を使う。
    次のときは、生成が失敗する（条件を確認してから、スクリプトの設定に足す）。
    -   許可していない種類のライセンス（MIT・ISC・Apache-2.0・BSD-3-Clause・BSL-1.0・libjpeg-turbo の
        複合以外）、LICENSE の見つからないパッケージ
    -   `vendor/`・`fork/`・`react-navigation/` の下のファイルがバンドルに入る（設定にない取り込み）
    -   Maven の groupId が知らないもの、Gradle の依存の行が読めない形、React Native の C++ の依存・
        埋め込み元の成果物の版が変わった
    -   `ios/Podfile.lock` に、node_modules（と codegen の生成物）の外から入る Pod がある
        （CocoaPods の trunk から入る Pod など）

## 11. UI原則

### Fast

曲の登録・検索・ステータス変更を少ない操作で行える。

### Clean

曲数が数百曲になっても見やすいリストUIを優先する。

### Private by Default

キー・メモなど個人用情報は外部に見せない。

### No Scores

採点・ランキングをUIに持ち込まない。

### Showable

「自分で管理する画面」と「人に見せる画面」を明確に分離する。

## 12. v1.0の中心体験

`Want → Practice → Ready` を基本的な曲の成長フローとする。

`Want` は Songs 内のステータスとして扱い、`Practice`
は「今練習する曲」に集中するため独立タブとする。

v1.0で最も重要な体験は以下。

**曲を登録 → Readyにする → Show My Songs → 「この中から選んで」**

公開WebやRequestsを実装する前から、Singfolioの中心コンセプトを体験できることを重視する。
