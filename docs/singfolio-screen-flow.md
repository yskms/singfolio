# Singfolio v1.0 画面設計

## 1. ナビゲーション

ボトムタブは3つ。

-   **Songs** --- レパートリー管理
-   **Practice** --- 練習中の曲
-   **Profile** --- 見せる・設定

メイン導線は `Songs` とする。

## 2. 画面遷移

``` text
                     Singfolio
                         │
          ┌──────────────┼──────────────┐
          │              │              │
        Songs         Practice        Profile
          │              │              │
          │              │         ┌────┴────┐
          │              │         │         │
      Song Detail    Song Detail  Show Mode  Settings
          │
       Add / Edit
```

v1.0ではログインを必須にしない。

公開Web・Requestsは将来追加する。

### 起動時の例外

起動に失敗したときや、画面の描画に失敗したときは、タブを出さず、専用のエラー画面で伝える
（アプリ全体で1つ。ルートの `ErrorBoundary`）。エラー画面はDBに触れない（起動時の失敗では
DBを読めないことがある）ため、言語は保存したLanguageの設定ではなく、常に端末の言語で出す。
配色は、起動に失敗したときは端末の設定に従い、起動が終わった後の描画の失敗では、保存した
Appearanceのまま（起動時に端末へ反映済みのため）。

-   **アプリより新しいDB**（ストアで古い版へ戻した場合など）：「アプリの更新が必要です」と
    伝える。やり直しても開けないため、ボタンは出さない。DBは変更していない旨も伝える。
-   **それ以外の起動時の失敗**（DBを開けないなど）：汎用の文言と「もう一度試す」ボタン。
    押すと起動の処理を最初からやり直す。原因は利用者に見せない。
-   **起動後の画面の描画の失敗**：同じ汎用のエラー画面（タブも隠れる）。「もう一度試す」を
    押すと、アプリの画面を作り直し、先頭の画面（Songs）から始める（開いていた画面は残らない。
    iOSで確認）。先頭の画面自体が失敗する場合は、やり直しても同じ失敗になる（アプリの
    再起動が要る）。画面のデータの読み込みの失敗も、同じエラー画面に任せる（Songsは、
    読み込みの失敗を、描画の中で例外として投げ直す）。画面（ルート）ごとの `ErrorBoundary` は置かない。失敗してもタブへ戻れる
    ようにしたい画面が出てきたら、その画面に足す（2. 以降の画面を足すときに判断する）。
-   **存在しない画面**（`singfolio://...` のリンクなど）：「画面が見つかりません」と、
    曲の一覧へ戻るボタン。通常の画面と同じく、保存した言語・配色に従う。
-   スプラッシュは、DBの初期化と設定の読み込みが終わり、最初の画面を描画できるまで残す。
    エラー画面を出すときは閉じる。

## 3. Songs

アプリのホーム画面。

### 表示

``` text
Singfolio                              ＋

  84             12             23
 Ready         Practice         Want

Search songs or artists

[ All ] [ J-Pop ] [ Rock ] [ Acoustic ]

Ready to sing  84         ⇅ Recently updated

チェリー
スピッツ
J-Pop · Acoustic

HANABI
Mr.Children
J-Pop · Ballad

天体観測
BUMP OF CHICKEN
Rock · Anime
```

ヘッダーの題はブランド名（左寄せ）。件数タイル・検索欄・タグのチップ・見出し・曲の行は、
1つのリストとして一緒にスクロールする（検索欄は固定しない）。

### 操作

-   **ステータスで絞り込む**: Ready / Practice / Want の件数タイルが、そのまま絞り込みの
    切り替え。押すとそのステータスの曲だけを表示する。起動時は Ready。選択中のタイルを
    もう一度押すと、ステータスで絞らない（見出しは「すべての曲」）。
    件数は、検索・タグに関係なく、全曲のステータスごとの数。
-   **曲を検索**: 曲名またはアーティストに含まれる文字列。入力するたびに絞り込む。
    大文字小文字・全角半角・ひらがな/カタカナの違いは区別しない（`ちぇりー` で `チェリー`
    が見つかる）。漢字の読みでは探せない（読みのデータが無い。
    `singfolio-data-model.md`「曲の一覧」）。
-   **タグで絞り込む**: 検索欄の下のチップ（横スクロール）。1つだけ選べる。`All` または
    選択中のチップをもう一度押すと解除。タグが1つも無いときは、チップの列を出さない。
    作成済みのタグはすべて出す（曲が付いていないタグも）。選んでいたタグが、Settingsで
    削除された場合は、絞り込みを外す。
-   **並び替え**: 見出しの右のボタンから、下から出るシートで選ぶ。Recently updated（更新が
    新しい順。既定）/ Recently added（追加が新しい順）/ Title（曲名のA→Z）/ Artist
    （アーティストのA→Z）。向きは、それぞれ固定（逆順は持たない）。Title / Artist は
    文字コード順で、日本語は読み順にならない（`singfolio-data-model.md`「曲の一覧」）。
-   曲をタップ → Song Detail
-   `＋`（ヘッダーの右） → Add Song

絞り込み・並び替えの状態は、アプリを開いている間だけ保持する（端末には保存しない。
起動すると、Ready・タグなし・検索なし・Recently updated に戻る）。条件はすべて満たす曲だけを
出す（AND）。見出しの数字は、表示中の曲の数。

他の画面で曲やタグが変わったあと（Song Detail・Practice・Settingsなど）にタブへ戻ると、
読み直す。

行には、曲名・アーティスト・タグ（` · ` 区切りの1行）を出す。My Key・Private Note は出さない。
タグが付いていない曲は、タグの行を出さない。

### 空の状態

| 状況 | 表示 |
|---|---|
| 曲が1つも無い | 「まだ曲がありません」と、Add Song を開く「曲を追加」ボタン |
| 検索・タグで絞り込んで0件 | 「一致する曲がありません」、見出しの名前（「歌える曲」など）を含む案内、「検索とタグをクリア」ボタン（ステータスは変えない） |
| ステータスだけで絞って0件 | ステータスごとの1行の案内 |

## 4. Add / Edit Song

曲の登録・編集画面。同じ入力画面（`ui/SongForm.tsx`）を、追加（`app/song/new.tsx`）と
編集（`app/song/[id]/edit.tsx`）で使う。タブバーを隠した全画面で、Stackに積む。

追加は、Songsの `＋`（ヘッダーの右）と、曲が1つも無いときの「曲を追加」ボタンから開く。
編集は、Song Detail の Edit から開く。存在しない曲のIDで編集を
開いた（開いている間に曲が消えた場合を含む）ときは、「曲が見つかりません」と、曲の一覧へ
戻るボタンを出す。

### 項目

**Song** - Title * - Artist *

**Status** - Ready - Practice - Want

**My Key** - Original - - / + 数値

**Tags** - 複数選択 - 新規タグ作成

**Private Note** - 自由入力

`*` のみ必須。

素早く登録できることを優先し、Title + Artistだけでも保存可能とする。

``` text
< (戻る)        Add Song        [ Save ]

Title *
[                              ]
Artist *
[                              ]

Status
[ Ready ] [ Practice ] [ Want ]

My Key
 ( − )     Original     ( + )

Tags
Tags may appear in Show Mode.
Keep private details in Private Note.
[ J-Pop ] [ Rock ] [ Acoustic ]
[ New tag                 ] ( + )

Private Note
[                              ]
```

-   **Save** はヘッダーの右（キーボードを出したまま押せる）。保存すると前の画面へ戻る。
-   追加は、開くとTitleにフォーカスが入り、すぐ入力できる。Titleでの改行（Enter）で
    Artistへ移る。
-   **Status** の既定は Ready（追加のとき。中心の体験「曲を登録 → Readyにする」のため。
    Songsで選んでいるステータスには依存しない）。
-   Title / Artist が空（空白だけを含む）のまま Save すると、保存せず、両方の欄の下に
    エラーを出し、空の最初の欄にフォーカスを移す。入力すると、その欄のエラーが消える。
    それ以外の保存の失敗は、ダイアログで伝える。
-   **My Key** は `−` / `+` で半音ずつ動かす。0は「Original」と出し、それ以外は `+2` / `-2`。
    選べる範囲は上下12半音（1オクターブ。`src/domain/keyOffset.ts`）で、端では、その向きの
    ボタンを無効にする。これは入力画面の範囲で、保存する値の制限ではない
    （`singfolio-data-model.md`「曲の入力」）。
-   **Tags**: 作成済みのタグをチップで複数選ぶ。新しいタグは、下の入力欄に書いて追加する
    （Enter・`＋`。iOSは、続けて追加できるよう、Enterでキーボードを閉じない。Androidは
    閉じる）。追加した新しいタグは、選択中のチップとして並び、押すと取り消せる。
    **新しいタグは、曲を保存するときに、曲と同じトランザクションで作る**（保存せずに戻った
    とき、保存に失敗したとき、どちらも使われないタグが残らないようにするため）。入力欄に
    書いたまま Save した名前も、追加したものとして扱う。既存のタグと同じ名前（正規化して、大文字小文字を同一視。
    `singfolio-data-model.md`「タグ名」）は、新しく作らず、そのタグを選ぶ。
-   変更があるまま戻る（戻るボタン・iOSのスワイプ・Androidの戻る操作）と、「変更を破棄
    しますか？」の確認を出す。保存して戻るときは出さない。

### 候補（サジェスト）

Title / Artist を入力している間、候補を欄の直下に出す（オーバーレイにしない。キーボードの
余白と同じスクロールの中に置く）。候補は補助で、出なくても、使わなくても、自由に入力して
保存できる。

-   **曲名の欄**: 曲の候補（`曲名 / アーティスト`）を出す。選ぶと、**曲名とアーティストの
    両方**を候補の値で置き換える（候補は組なので、片方だけだと組が崩れる）。登録済みの
    （曲名, アーティスト）の組には「登録済み」を付ける（重複登録は止めない）。
-   **アーティストの欄**: 登録済みのアーティストを先に、外部の検索で見つかったアーティストを
    後に出す。選ぶと、**アーティストの欄だけ**を置き換え、曲名には触れない。共演の表記
    （`A & B`、`feat.`、`×`）は分割せず、単独の名前より後ろに並べる。
-   検索語は、曲名の候補は曲名（この画面でアーティストを入力した・候補から選んだときは、
    それも加える。編集画面を開いたときから入っているアーティストは、編集していないので
    加えない）、アーティストの候補はアーティスト。2文字未満は検索しない（登録済みのアーティストの候補は1文字から出す）。
    ひらがな・カタカナ・全角半角・大文字小文字を同一視して探せ、かな入力で漢字の曲名も
    見つかる（`ぐれんげ` → `紅蓮華`）。
-   **送信のタイミング**: 入力欄を**編集した**ときだけ。フォーカスしただけ・開いたときの
    既存の値では送らない。入力が止まってから送る（登録済みのアーティストの候補は待たずに出す）。
-   **候補の整形はしない**。`(Live)`・`- Remastered` などの版の表記もそのまま出す。選んだ
    後に編集できる。版の表記を含む候補（Live・Cover・Karaoke・オルゴールなど）は、削らずに
    後ろへ並べる。同じ（曲名, アーティスト）の候補は1つにする。
-   **古い結果は捨てる**。入力の変更・候補の選択・別の欄へのフォーカス移動・画面を閉じる、の
    いずれでも、返ってきた古い結果は出さない。候補を選んで欄が書き換わっても、再検索しない。
-   **失敗しても止めない**。通信できない・遅い・回数の制限に当たったときは、外部の候補が
    出ないだけで、入力も保存もできる。制限などの失敗の後は、一定時間は外部へ送らない（その間も
    登録済みのアーティストの候補は出す）。失敗を「見つからなかった」として覚えない。探せなかったとき（予算切れ・停止中・失敗）は、
    直前の候補をそのまま残す（検索語を打ち足している・消して戻している間だけ。別の語に打ち直した・
    0件・検索語が短くなる・フォーカスが外れるときは消える）。
-   **変換で別の語になったとき**（`ぐれんげ` → `紅蓮華`）は、候補がいったん消えて、新しい語の
    結果が出る。自然な動きとして決めたもので、前の候補を残す・高さを保つ工夫はしない。
-   **表記する**: 外部へ検索語を送る間は、候補の欄に提供元（`Suggestions from Apple` /
    `候補の提供元: Apple`）を出す。候補が0件のときも出す。設定でオフのときは出さない。
-   **ストア**: 実際に使う表示言語が日本語なら日本のストア、それ以外は米国のストアで探す
    （表記が変わる。例: `千本桜` / `Senbonzakura`）。端末の地域では決めない。
-   候補は最大5件（アーティストは4件）。キーボードの上に収めるため、行は2行までの低い高さに
    する。各行はボタンとして読み上げる（`曲名、アーティスト`。登録済みならそれも）。

### タグに関する注意事項

タグはShow Modeに表示される。人に見せたくない内容はPrivate Noteに入力するよう、
タグ欄の近くで短く案内する。

``` text
Tags may appear in Show Mode.
Keep private details in Private Note.

タグはShow Modeに表示されます。
人に見せたくない内容はPrivate Noteに入力してください。
```

案内は、Tagsの見出しの下に、常に表示する（初回だけ・情報アイコンなどにはしない。曲を
登録するたびに目に入り、タグ欄の近くで読めるため）。

## 5. Song Detail

登録した曲の詳細画面。

``` text
チェリー
スピッツ

STATUS
● Ready to sing

MY KEY
-2

TAGS
J-Pop
Acoustic

PRIVATE NOTE
2番の歌詞を確認
サビは問題なし。

────────────────

Edit
Delete song
```

ここからステータス変更も可能とする。

`Practice → Ready` などを簡単に行えるようにする。

実装（`app/song/[id]/index.tsx`）は、Stackに積む全画面。ヘッダーには戻るボタンだけを出し、
題は付けない（曲名は本文の先頭に出す）。

-   **曲名・アーティスト**: 長いときは折り返して、全文を出す（一覧のように省略しない）。
-   **Status**: Add / Edit Song と同じ3択（`ChoiceRow`）を、そのまま変更の操作にする。
    押すとすぐ保存し（Saveは無い）、`updatedAt` も更新する（`setStatus`）。選択中のステータスを
    押し直しても何もしない。保存に失敗したら、ダイアログで伝える。
-   **My Key**: `Original` / `+2` / `-2`（Add / Edit Song と同じ表記）。
-   **Tags・Private Note**: 無い曲では、項目ごと出さない（空の見出しを並べない）。Private Note は
    改行を入力どおりに出す。ここは管理する画面なので、My Key・Private Note を出してよい
    （Show Mode とは別の画面）。
-   **Edit**: 末尾の区切り線の下のボタン。Edit Song を開く。
-   **Delete song**: Edit の下のボタン（文字は `error` の色）。曲の削除は、この画面だけに置く
    （Edit Song には置かない）。消す曲のキー・メモ・タグをその場で見て判断でき、削除のあとに
    畳む画面が1枚で済み、Edit Song の「変更を破棄しますか？」の確認と重ならないため。
    押すと確認のダイアログ（「曲を削除しますか？」。曲名を添え、元に戻せないと伝える。
    キャンセル / 削除）を出し、削除を選ぶと曲を消して、前の画面（SongsやPractice）へ戻る。
    取り消し（Undo）は無い。付いていたタグは残る（`singfolio-data-model.md`）。
    削除に失敗したらダイアログで伝え、この画面に残る。削除できたあと戻るまでの間は、
    ステータスの変更・Edit・もう一度の削除を受け付けない（戻る操作が重ならないように）。
    戻る先が無いとき（リンクから直接開いたとき）は、曲の一覧を開く。
-   Songs の行をタップして開く。開いたとき、および上に重ねた Edit Song から戻ったときに、
    曲を読み直す（戻ったときは、前の内容を出したまま読み直して、空の画面を挟まない）。
    Songs は、この画面から戻ったときに自分で読み直す（§3）。
-   Songs の行・Edit ボタンを素早く連打しても、同じ曲の Song Detail・Edit Song は重ならず、
    1枚だけ開く（Add Song も同じ。`app/_layout.tsx` の `dangerouslySingular`）。
-   存在しない曲のID・開いている間に消えた曲（ステータスを押した時点で消えていたことが
    分かる場合を含む）は、Edit Song と同じ「曲が見つかりません」と、曲の一覧へ戻るボタンを出す。

## 9. Settings

### Appearance

-   System
-   Light
-   Dark

デフォルトはSystem。

-   アプリ全体（ネイティブの描画を含む）のカラースキームを切り替えるため、ステータスバーや
    ダイアログも設定に従う。端末（OS）の設定は変えない。
-   起動画面（スプラッシュ）だけは、アプリが起動する前に表示されるため、この設定ではなく
    端末の設定に従う（端末がダークでAppearanceがLightのときは、ダークの起動画面のあと
    ライトの画面になる）。Androidでは、アプリを終了して同じプロセスのまま再び開いた
    直後にも、Appearanceが System 以外のときは、設定を反映するまでの短い間、端末の配色の
    画面が見える。

### Language

-   System
-   English
-   日本語

デフォルトはSystem（Appearanceと同じ形）。

-   English / 日本語は、その言語自身の名前で出す（言語が分からなくなっても選び直せるように）。
    System だけは、表示中の言語の文言で出す。
-   System のあいだは、端末の言語に従う。端末の言語の優先順に見て、最初に対応している
    言語（`ja-JP` → 日本語）を使い、どれも対応していなければ English。端末の言語が
    後で変わったときも追従する。
-   English / 日本語を選ぶと、その言語を保存し、端末の言語が変わっても変えない。System を
    選ぶと、端末の言語への追従に戻る。切り替えは、アプリを再起動せず全画面にすぐ反映する。
-   初回起動で端末の言語から決めた言語を保存しない（保存すると、System のまま追従できなく
    なる。未保存は System）。
-   書体は表示言語に従う（English → Inter、日本語 → Noto Sans JP）。ヘッダーの題・タブの
    ラベルも含め、言語を切り替えるとすぐ変わる。ユーザーが入力した日本語を English の画面で
    出すときは、Inter に日本語の字が無いため、OS（端末）のフォントで表示される（端末の言語に
    日本語が無いと、漢字が中国語の字形になりうる。未確認。許容している）。
-   iOSは、アプリの対応言語（`CFBundleLocalizations`）を app.json で宣言している。
    宣言が無いと、iOSの標準の文言（コピー/ペーストのメニュー、ダイアログのボタンなど）が
    日本語の端末でも英語のままになる（Appleの説明による。未確認）。宣言すると、OSの設定
    アプリのSingfolioに、アプリごとの言語の項目が出る（Appleの仕様。未確認）。
    System のあいだは、アプリはOSが返す言語の優先順に従う（起動引数 `-AppleLanguages` で
    言語を変えて、従うことをiOSシミュレータで確認済み。設定アプリの項目からの変更は
    未確認）。English / 日本語を選んだ後は、アプリ内の設定が優先する。このときOSの設定
    アプリで言語を変えても、アプリの文言は変わらず、OS標準の文言だけが変わる（System へ
    戻せば、OSの設定に従う）。
-   Androidは、アプリごとの言語（Android 13以降のOSの機能）を宣言していない。言語の操作は
    アプリ内のLanguageに一本化する。Androidの標準の文言は端末の言語に従う。
-   OS標準の部品の文言は、アプリ内のLanguageではなく、端末（iOSでOSの設定アプリで選んだ
    アプリの言語を含む）の言語に従う。そのため、アプリ内で選んだ言語が端末と違うと、
    ずれる（`Alert.alert` のボタンを省略したときの既定の「OK」など）。文言を指定できる
    ものは、省略せず指定する（CLAUDE.md「言語」）。

### Suggestions

曲名・アーティストの候補（Add / Edit Song）を、外部の楽曲検索から出すかどうか。オン / オフ。
デフォルトはオン。

-   説明文: 「入力中の曲名・アーティスト名を Apple に送って、候補を探します。それ以外は
    送りません。」（English: "What you type in Title and Artist is sent to Apple to find
    suggestions. Nothing else is sent."）
-   オフにすると外部へは何も送らない。登録済みのアーティストの候補は、端末内だけで出す。
-   外部の検索が使えない状態（ビルドで無効にしたとき）は、この項目も、候補の提供元の表記も
    出さない。

## 11. UI原則

### Fast

曲の登録・検索・ステータス変更を少ない操作で行える。

### Clean

曲数が数百曲になっても見やすいリストUIを優先する。

### Private by Default

キー・メモなど個人用情報は外部に見せない。

### No Scores

採点・ランキングをUIに持ち込まない。

### Showable

「自分で管理する画面」と「人に見せる画面」を明確に分離する。

## 12. v1.0の中心体験

`Want → Practice → Ready` を基本的な曲の成長フローとする。

`Want` は Songs 内のステータスとして扱い、`Practice`
は「今練習する曲」に集中するため独立タブとする。

v1.0で最も重要な体験は以下。

**曲を登録 → Readyにする → Show My Songs → 「この中から選んで」**

公開WebやRequestsを実装する前から、Singfolioの中心コンセプトを体験できることを重視する。
